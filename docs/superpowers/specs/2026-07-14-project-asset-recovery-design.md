# Project Asset Recovery Design

## Goal

Restore existing projects without regenerating assets. Reopened projects must show
their existing character images, scene images, video clips, and final video when
the backed-up files are still present under `output/`.

## Current Failure

`ImageGenerationAgent` writes multi-view images to these directories:

```
output/characters/<project_id>/<character_name>/<view>.png
output/scenes/<project_id>/scene_<id>/<view>.png
```

`ProjectStore.get_asset_groups()` only scans the per-project layout:

```
output/<project_id>/characters/
output/<project_id>/scenes/
```

The scanner therefore reports no images for projects generated by the current
image agent. In addition, the project-open frontend restores text state but does
not hydrate the media arrays that its render functions consume.

## Design

### Asset Discovery

`ProjectStore.get_asset_groups(project_id)` will support both layouts. It will
first collect images from the active image-agent layout, then merge files from the
legacy per-project layout without overwriting an already discovered view.

It will retain the existing grouped response shape for characters and scenes.
Video, audio, and final-video discovery will continue to use the per-project
directories, with the saved state providing the primary source for files written
outside those directories.

### Project Restore

When `studio.html` opens a project, it will:

1. Parse saved `state_json` when available.
2. Restore character images, scene images, generated video assets, audio assets,
   and final video from that state.
3. Use the server-provided scanned asset groups to fill any missing image lists.
4. Re-render the role, scene, shot, production, and works views only after those
   media arrays have been restored.

Existing files are never moved, copied, renamed, or regenerated.

### Path Handling

The existing `pathToUrl()` conversion remains the browser-side boundary from a
local asset path to FastAPI's `/output/` static route. The recovery code will only
use paths returned by saved state or the asset scanner, so paths remain inside the
mounted `output/` tree.

## Error Handling

Missing files will simply be omitted from recovered asset lists. Existing UI
placeholder behavior remains for an image or video that cannot be loaded. A
missing or malformed `state_json` must not prevent recovery from the filesystem
scanner.

## Verification

1. Add focused tests for both image storage layouts in `ProjectStore`.
2. Verify the restored API response includes the expected grouped files.
3. Open an existing project with backed-up images and verify that role and scene
   cards show images without rerunning generation.
4. Confirm opening an older project with no state still displays images discovered
   by the scanner.
