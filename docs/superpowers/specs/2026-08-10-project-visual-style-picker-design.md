# 项目视觉风格选择与参考图设计

## 1. 背景与目标

当前项目创建页只保存一个自由文本 `art_style`，例如“动漫”或“写实”。这个标签没有足够的媒介、线稿、上色、光影和负面约束，导致角色可能偏动漫、场景偏写实，分镜提示词也无法稳定维持同一种视觉语言。

本设计将项目视觉风格改为“一个主风格 + 可选补充标签”，并在新建项目弹窗中用综合参考图帮助用户选择。主风格会被统一编译到角色、场景、道具和分镜提示词中，保持现有生成接口、模型选择、画幅和历史版本行为不变。

## 2. 范围

### 包含

- 项目创建页展示四种主视觉风格，每种使用一张同一人物与同一场景的 16:9 综合示例图。
- 后端提供风格注册表 API，前端从注册表读取名称、说明、标签和图片地址。
- 项目状态保存稳定的 `visual_style_id`，并保留旧 `art_style` 字段用于兼容。
- 统一的风格约束编译器，为角色、场景、道具和分镜提示词提供正向与负面约束。
- 旧项目风格值的兼容映射、图片加载失败兜底、非法风格校验和风格快照记录。
- 新增测试覆盖 API 契约、状态迁移、提示词注入和创建页交互。

### 不包含

- 不允许用户上传自定义风格参考图；该能力作为后续独立功能。
- 参考图仅用于创建页说明，不会作为生图或视频生成请求的输入。
- 不改变图片模型、视频模型、TTS、音频时间轴、画幅或项目资产目录。
- 不自动重生成旧项目的图片、视频、音频或字幕。

## 3. 用户界面设计

### 3.1 新建项目弹窗

保留现有项目名称、视频比例、剧集类型和对白生成方式控件。艺术风格区域改为风格卡片网格，桌面端四列展示，窗口较窄时自动降为两列或一列。

每张卡片包含：

1. 16:9 综合示例图。四张图使用相同的示例人物和场景，只改变视觉媒介，便于横向比较。
2. 风格名称：现代电影级二维赛璐璐、半写实动漫、日系商业动画、电影级真人写实。
3. 一句适用说明。
4. 三个短标签，分别描述角色、场景和光影特征。
5. 选中边框、选中标记、键盘焦点和图片加载失败状态。

卡片整体可点击，不能只依赖小标签点击。选中后立即更新 `appState.artStyle` 和 `appState.visualStyleId`，提交创建时一起发送。缺失参考图时显示同尺寸的风格名和“参考图暂不可用”，不阻止创建。

### 3.2 兼容旧风格

现有“赛博朋克、国风、清新”等选项不删除，放在主风格卡片下方的“风格补充”区域，以新增的 `style_modifiers` 数组保存，同时把主风格和补充标签拼接到 `art_style` 兼容文本中。补充标签只能修饰主风格，不替换主风格；新项目没有主风格时使用默认的现代电影级二维赛璐璐。

旧项目打开时按以下顺序恢复：

1. 存在 `visual_style_id` 时直接使用该 ID。
2. 否则把旧 `art_style` 通过兼容映射转换为主风格 ID和补充标签。
3. 无法识别时使用 `live_action_cinematic`，并保留原始文本，避免丢失用户配置。

## 4. 风格注册表

后端维护唯一的风格注册表，前端通过 `GET /api/visual-styles` 获取，不在 HTML 中复制风格规则。每个条目包含：

```json
{
  "id": "cinematic_cel",
  "name": "现代电影级二维赛璐璐",
  "description": "清晰线稿与电影级构图，适合都市悬疑和现实题材",
  "reference_image": "/static/assets/style-references/cinematic-cel.webp",
  "tags": ["清晰线稿", "硬边赛璐璐阴影", "电影构图"],
  "prompt_layers": {
    "character": "2D 手绘动画媒介，清晰轮廓线，成年人物比例，两到三层赛璐璐阴影",
    "scene": "二维背景绘制，稳定透视，冷暖电影级光影，环境结构清晰",
    "prop": "二维设定稿媒介，轮廓明确，材质由简洁色块和硬边阴影表达",
    "shot": "保持二维动画媒介和角色比例，使用电影级构图与明确镜头运动"
  },
  "negative_prompt_layers": {
    "character": "真人照片，3D 渲染，Q 版比例，塑料皮肤，风格漂移",
    "scene": "照片级实拍，3D 游戏场景，透视畸变，风格漂移",
    "prop": "产品实拍，3D 建模展示，结构漂移，风格漂移",
    "shot": "真人电影实拍，3D 角色，媒介混用，角色比例漂移"
  }
}
```

首批四个稳定 ID：

- `cinematic_cel`：现代电影级二维赛璐璐。要求非真人的 2D 手绘动画媒介、清晰轮廓、两到三层硬边阴影、成年人物比例和电影级冷暖光影。
- `semi_realistic_anime`：半写实动漫。要求动漫线稿、自然成年比例、细腻材质、柔硬结合的光影和概念动画质感。
- `japanese_animation`：日系商业动画。要求干净线条、稳定脸型、明确色块、商业动画背景绘制和统一角色设定。
- `live_action_cinematic`：电影级真人写实。要求真实人体比例、皮肤与材质细节、真实镜头和自然景深；禁止插画、动漫、3D 渲染和塑料质感。

注册表中的约束使用中文，供应商适配器按现有路径转换为实际请求格式。风格条目不包含模型专属参数，避免把视觉风格和供应商能力耦合。

## 5. 状态与 API

### 5.1 项目状态

在 `CreativeProfile` 中新增：

- `visual_style_id: str`，默认 `cinematic_cel`；
- `style_modifiers: list[str]`，默认空列表。

保留 `art_style: str`，用于旧客户端和旧项目读取。保存新状态时同时写入规范化 ID 与可读兼容文本，保证旧接口仍能工作。

### 5.2 风格查询

新增 `GET /api/visual-styles`：返回注册表中可用于项目创建的风格及参考图 URL。该接口不依赖 API Key、不创建生成任务，失败时前端使用内置名称和无图兜底卡片。

### 5.3 项目创建与读取

扩展项目创建请求接收 `visual_style_id` 和 `style_modifiers`。服务端校验 ID 是否存在，规范化补充标签并写入项目状态。未提供 ID 时按旧 `art_style` 映射，仍未识别时使用默认风格。

项目读取接口返回 `creative_profile.visual_style_id`、`style_modifiers`、兼容 `art_style` 和风格摘要，前端据此恢复选择卡片。

### 5.4 风格快照

每个新建的角色、场景、道具或视频任务，在现有请求快照中增加：

- `visual_style_id`；
- `style_modifiers`；
- 提交时注册表条目的正向/负面约束快照。

后续修改项目风格只影响新任务，不改变历史任务和历史图片版本。

## 6. 提示词编译与数据流

提示词编译顺序固定为：

1. 资产或镜头的剧本事实和用户编辑内容；
2. 角色、场景、道具的身份绑定与视图约束；
3. 项目画幅和模型能力约束；
4. 主风格的媒介、线稿、上色、光影和构图约束；
5. 风格补充标签；
6. 资产类型通用负面约束与用户负面策略。

用户文本保留主体地位，但不能删除身份锚点、视图方向、画幅和风格的禁止项。对于不支持独立负面提示词的供应商，现有降级逻辑把负面约束合并到主提示词；对于支持负面提示词的供应商，仍分别传递并保存两部分快照。

风格层只描述视觉媒介和统一美术语言，不重新编写镜头动作、台词、地点或道具身份，避免再次出现镜头内容串用和提示词覆盖。

## 7. 参考图资源

四张综合参考图放在静态前端资源目录 `web/assets/style-references/`，不放进 `output/`，不属于任何项目资产，也不参与资产清理和项目删除。文件统一使用 WebP，建议 1600x900，文件名按稳定 ID 命名。

参考图制作要求：同一成年角色、同一室内或街道场景、同一机位和动作，仅改变画面媒介；不得使用具体在世艺术家或具体动画作品名称；画面不出现文字、水印、边框和 UI。

## 8. 错误与兼容

- 风格注册表请求失败：前端显示内置的四个名称和灰色占位图，仍可创建。
- 参考图加载失败：保留卡片尺寸和文字说明，不阻止创建。
- 非法 `visual_style_id`：创建接口返回 422 及可选 ID 列表，不静默改用其他风格。
- 旧客户端只发送 `art_style`：服务端按映射转换，并继续返回 `art_style`。
- 旧项目缺少风格字段：懒迁移，不修改其历史生成文件；打开后显示映射后的主风格。

## 9. 测试方案

### 后端

- 风格注册表包含四个稳定 ID、参考图 URL、提示词层和负面层。
- 创建项目保存并读取 `visual_style_id`、补充标签及兼容 `art_style`。
- 旧值“写实、动漫、日系”等映射正确，未知值保留原文并使用默认主风格。
- 非法 ID 返回 422；不触发任何图片或视频任务。
- 角色、场景、道具和分镜提示词均包含对应风格层，且不同镜头的动作内容不被风格层覆盖。
- 任务和图片版本快照包含风格 ID 与约束快照，切换项目风格不改变历史版本。

### 前端

- 项目创建页成功加载四张卡片，卡片点击、键盘选择、恢复选择和图片失败兜底正常。
- 创建请求包含所选主风格和补充标签；旧接口调用仍能创建项目。
- 项目切换不会串用上一项目的选中风格或参考图。
- 参考图只显示在创建页，不出现在资产库或生图/视频请求参考列表。
- 在桌面端和窄窗口下卡片不溢出，文字和图片不重叠。

### 浏览器验收

使用同一剧本创建四个测试项目，分别选择四种主风格，仅执行剧本解析和视觉提示词阶段，检查项目状态、生成提示词和风格快照；禁止自动提交图片或视频任务。

## 10. 发布顺序

1. 先加入风格注册表、兼容映射和查询接口。
2. 扩展项目状态和创建接口，确保旧项目、旧客户端仍可读取。
3. 加入四张静态综合参考图和创建页卡片交互。
4. 接入统一风格提示词编译器和任务快照。
5. 运行测试和浏览器验收后，再默认启用 `cinematic_cel`。
