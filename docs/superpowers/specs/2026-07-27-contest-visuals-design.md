# 鸿蒙赛道作品说明文档配图设计规格

## 目标

为 AI 短剧 Agent 的参赛说明文档提供三张统一风格的替换配图，分别证明技术架构、产品形态与端到端创作流程。图片服务于评审阅读，不承担正文说明，因此避免密集文字、代码片段和无法辨认的小字号。

## 保留与替换范围

- 保留原文档中的四张签名图片，不做任何生成、修图或替换。
- 替换原 `image5.png`：复杂的多智能体架构图。
- 替换原 `image6.png`：概念化工作台图。
- 替换原 `image7.png`：截图拼贴流程图。
- 图片生成完成后先保存为新文件，不覆盖原 DOCX 中的图片；用户确认后再手工插入或由后续步骤生成副本替换。

## 统一视觉语言

- 画幅：横向 16:9，建议 1920×1080 或更高分辨率。
- 基调：深海军蓝背景，辅以青蓝、紫色、绿色和暖橙色功能色；不使用渐变球、装饰性光斑或营销海报式人物。
- 风格：专业软件系统说明图，稳定、克制、信息密度适中；边框圆角不超过 10 px。
- 字体策略：图像模型不承担大量中文排版。图中最多保留 3 到 6 个短标签；主标题、图号、图注和详细中文说明由 Word 文本完成。
- 真实性边界：概念界面可作为演示稿，但模块、状态、资产类别和工作流必须符合现有 AI 短剧 Agent 的实际能力；不得伪造模型指标、用户数量、成本数据、获奖标识或外部平台认证。

## 图 1：多智能体协同技术架构图

### 用途

替换原复杂架构图，放在“技术方案/系统架构”章节，突出系统不是单次模型调用，而是具有状态管理、任务编排与审核回流的多 Agent 工作流。

### 构图

- 顶部为“创作工作台”入口，表现创意输入、剧本草稿和任务状态。
- 中部为横向主链路：剧本理解、视觉设计、资产生成、分镜视频、质量审核、音频合成、成片输出。
- 主链路下方为两个稳定支撑模块：项目状态/版本管理与资产库/任务队列。
- 审核节点只有一条回流箭头，指向需要重试的生成节点，避免交叉线。
- 最底部用一条简洁的服务层表示语言模型、图像模型、视频模型与语音模型，不写具体供应商名称。

### 标签

可使用短标签：创作工作台、剧本、视觉、资产、视频、审核、音频、成片。其余解释写在图注中。

## 图 2：短剧智能创作工作台产品展示

### 用途

替换原概念化产品图，放在“系统实现/交互设计”章节，证明系统有完整、可操作的创作界面。

### 构图

- 单张桌面端应用界面，不采用手机或网页营销首页。
- 左侧为紧凑导航：剧本、角色、场景、道具、分镜、音频、成片。
- 中部主工作区展示结构化剧本与当前镜头编辑区域，包含角色/场景参考卡片和提示词摘要。
- 右侧为视频预览与任务状态，画面使用短剧场景的静帧预览，不出现真实人物姓名。
- 下方为轻量时间线，能辨认配音、BGM、镜头片段的层次关系。
- 整体像真实桌面软件界面，屏幕内只使用少量模糊占位行和简短英文/数字状态，避免生成错误的中文 UI 文案。

### 标签

图外 Word 图注为“图 X AI 短剧智能创作工作台”；图内不要求中文标题。

## 图 3：从创意到成片的创作闭环

### 用途

替换原截图拼贴流程图，放在“功能流程/创新点”章节，帮助评审在十秒内理解用户如何完成一次短剧创作。

### 构图

- 采用五个等宽步骤卡片，从左到右依次表现：创意输入、剧本解析、角色与场景资产、分镜视频、配音与成片。
- 每个卡片内只用对应的简洁界面缩略图或资产缩略图，不放大段文字。
- 步骤间用统一直线箭头连接；最后一个卡片通过一条细回流线指向“审核/调整”，体现可迭代而非一次性生成。
- 用编号 01 至 05 强化顺序；步骤名称统一在 Word 中以图片下方图例呈现，避免图像模型生成中文。

### 图例文本

01 输入创意；02 解析剧本；03 生成角色与场景；04 制作分镜；05 配音合成成片。

## 生成与验收

- 使用默认内置图像生成能力；不使用聊天记录中出现的 API Key。
- 如需用户自有 API，用户必须先撤销已暴露密钥，并在本机环境变量中配置新的 `OPENAI_API_KEY`；不得再在聊天中发送密钥。
- 每张图片生成后检查：没有水印、没有虚构品牌、没有错误的长文本、没有重叠箭头、没有人物肖像作为主视觉、没有明显不符合软件界面的控件。
- 图片保存为新版本，命名为 `contest-architecture-v2.png`、`contest-workbench-v2.png`、`contest-workflow-v2.png`。
- 文档中替换图片前保留原始 DOCX，最终输出为独立副本，不覆盖用户正在编辑的模板。
