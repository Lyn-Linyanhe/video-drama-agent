# 分镜参考图与提示词完整性修复设计

## 目标

修复分镜制作中跨镜头参考图错配、资产更新后仍使用旧图，以及添加图片后多个镜头实际发送相同视频提示词的问题。前端显示、持久化状态和提交给视频供应商的请求必须使用同一份镜头级数据。

## 参考图规则

每个镜头参考项增加明确来源：

- `asset`：来自角色、场景或道具资产库，使用稳定的 `asset_type`、`asset_id` 和 `view_type` 作为身份。
- `manual`：用户在分镜制作页额外添加或上传的参考图，保存独立参考身份和用户排序。

资产绑定项始终跟随同一资产身份的最新激活图片版本。角色、场景或道具重新生成、切换历史版本或删除后，只更新引用该资产身份的镜头参考项；无关参考图不变。手工参考永不被自动替换或删除。

自动导入按每个镜头的角色、场景和道具需求逐项对账，而不是以“已有任意有效图片”为条件。它只补齐或更新资产绑定项，并保留手工项及用户定义的顺序。参考项之间不再通过文件路径反查或去重，避免不同资产因相同路径或旧路径发生错配。

## 提示词与生成请求

镜头提示词以 `scene_id` 为唯一键。视频生成从项目状态读取该镜头原始提示词，创建独立副本后再合成风格、角色、场景、道具和负面约束。视频 Agent 不得原地修改项目状态中的 `ShotPrompt` 或共享 `GenerationPrompts.shots` 对象。

提交任务时固化下列不可变快照：

- `scene_id`、原始主提示词和负面提示词；
- 实际发送给供应商的主提示词、独立负面提示词及其降级方式；
- 有序参考项的参考 ID、来源、资产身份、激活版本 ID、文件路径与标签；
- 视频服务商、模型、分辨率和能力策略。

任务完成后，视频版本保存同一份快照。工作台的只读“实际发送”区域仅显示该快照；在任务尚未生成前，显示基于当前草稿计算的预览并明确区分。这样可直接核对 UI、任务记录与供应商实际请求是否一致。

## API 与兼容性

现有生产工作台和视频生成 API 保持路径及请求结构兼容。后端读取旧项目的仅路径参考时，将其尽可能解析为资产绑定参考；无法可靠识别的项迁为 `manual`，不删除历史文件或视频版本。

更新镜头时，前端只提交当前 `scene_id` 的有序参考 ID。后端验证参考 ID、权限和项目归属后保存，不允许引用其他项目的资产。视频生成使用任务快照，避免任务排队期间的前端刷新或资产更新改变已提交请求。

## 错误处理

- 所需图生视频参考缺失时，返回镜头 ID 和缺失资产身份，而不是使用其他镜头图片兜底。
- 资产更新但新文件不可读时，保留上一个有效绑定版本并标记该参考为过期，阻止需要该图的任务提交。
- 保存或生成时发现 `scene_id`、提示词或参考项无法解析时，返回明确错误，不进行数组下标回退。

## 验收与测试

- 两个镜头有不同文本和资产绑定时，Mock 视频客户端收到的有效提示词和有序参考项必须不同。
- 更新一个角色、场景或道具的激活图片版本，只更新引用该资产身份的镜头参考项。
- 用户在工作台额外添加的手工参考在资产更新、自动导入和重新生成后保持不变。
- 自动导入能逐项补齐镜头所需资产，但不把另一个镜头的参考图写入当前镜头。
- 视频任务和视频版本保存的提示词、负面提示词、参考图序列、模型策略与 Mock 客户端实际收到的请求相等。
- 旧路径参考可兼容读取；无法识别的项保留为手工参考，不丢失历史数据。
