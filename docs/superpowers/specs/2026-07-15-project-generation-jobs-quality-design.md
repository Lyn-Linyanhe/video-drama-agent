# 项目级生成任务、终止与质量控制设计

日期：2026-07-15

## 目标

为剧本生成与解析、角色/场景/道具图片、分镜视频、配音/BGM 和成片合成建立统一的项目级任务机制，解决以下问题：

- 长时间生成只有前端估算进度，刷新后状态丢失。
- 网络、认证、限流、余额、供应商失败等错误混为笼统的“生成失败”。
- 重复点击可能重复提交，误点后无法终止。
- 视频任务只记录在进程内存中，服务重启后无法准确恢复。
- 图片与视频缺少统一的生成前校验和生成后质量检查。

本次不全面拆分 `studio.html` 或 `api_server.py`，只新增任务存储、任务执行和质量检查所需的职责明确模块。

## 已确认的产品规则

- 任务中心严格展示当前项目，不展示其他项目任务。
- 服务重启后，原 `queued/running/validating` 任务统一标记为 `interrupted`，不得自动重新提交。
- 用户可以手动重试 `failed/interrupted/canceled` 任务；重试创建新任务并保留原任务历史。
- 单项生成按钮在运行时变为“终止”；再次点击确认后终止该任务。
- 批量按钮在运行时变为“终止本批次 x/y”；终止时取消未开始子任务，并停止仍在本地等待的子任务。
- 终止会停止本地轮询、下载和状态写入。供应商没有可靠远端撤销能力时，已提交任务可能继续执行并产生费用，界面必须在确认框中说明。
- 批量终止后已经成功保存的资产继续保留；后续“生成缺失资源”只补齐未完成项。
- 确定性质量失败自动重试一次；主观质量问题只警告，不自动重新生成。

## 方案选择

采用 SQLite 持久化任务管理器与进程内 `asyncio` 执行器。

没有采用纯内存/项目 JSON 方案，因为批量并发会产生写入竞争，任务历史和重启恢复也难以可靠实现。没有采用 Celery/RQ + Redis，因为当前是单机应用，引入外部队列会显著提高部署复杂度。

## 架构

### 模块边界

新增以下模块：

- `src/services/job_store.py`
  - 管理 SQLite schema、事务和查询。
  - 不执行生成逻辑，不依赖 FastAPI。
- `src/services/job_manager.py`
  - 创建、调度、取消、重试任务。
  - 管理运行中的 `asyncio.Task` 与取消信号。
  - 通过处理器注册表调用具体任务。
- `src/services/job_handlers.py`
  - 把剧本、图片、视频、音频和合成操作适配为统一任务处理器。
  - 正式资产仍写入现有 `ProjectStore`/`DramaState`。
- `src/services/media_quality.py`
  - 执行生成前检查、确定性媒体检查和可选视觉审核。
  - 不负责重试决策；只返回结构化报告。
- `src/schemas/jobs.py`
  - 定义任务、事件、错误和质量报告模型。

`api_server.py` 负责 API 路由、参数校验与兼容包装，不直接维护任务集合。原 `video_jobs` 内存集合由 `JobManager` 替代。

### 任务类型

第一版支持：

- `script.generate`
- `script.analyze`
- `asset.generate`
- `video.generate`
- `audio.generate`
- `final.assemble`

批量图片和批量视频创建一个父批次，并为每个资产视图或分镜创建独立子任务。父批次进度由子任务状态汇总，不另行执行生成逻辑。

### 状态机

正常状态：

`queued -> running -> validating -> succeeded`

终止与异常状态：

- `failed`
- `canceled`
- `interrupted`

状态只能按允许的转换更新。终态任务不可被原地重新运行。手动重试创建带 `retry_of_job_id` 的新任务。

任务进度由真实阶段产生：

- 排队
- 准备输入
- 提交供应商
- 等待供应商
- 下载结果
- 校验结果
- 保存项目状态

百分比只能在阶段内单调增加，不能使用基于等待时间的假进度。

## 数据存储

数据库位置为 `output/jobs.sqlite3`，启用 WAL、外键和事务。

### jobs

主要字段：

- `job_id`
- `project_id`
- `batch_id`
- `job_type`
- `target_type`
- `target_id`
- `state`
- `stage`
- `progress_current`
- `progress_total`
- `attempt`
- `retry_of_job_id`
- `provider`
- `provider_task_id`
- `request_json`
- `result_json`
- `error_json`
- `quality_json`
- `cancel_requested`
- `created_at`
- `started_at`
- `completed_at`
- `updated_at`

`request_json` 保存可重试所需的输入快照。`result_json` 只保存摘要和正式资产标识；完整项目状态仍由现有项目存储管理。

### job_events

记录任务阶段变化、进度、重试、取消和错误分类。事件不保存 API Key、认证头、完整供应商响应或堆栈中的敏感数据。

### 启动恢复

数据库迁移必须幂等。服务启动时在一个事务中把遗留的 `queued/running/validating` 更新为 `interrupted`，写入“服务重启导致任务中断”的事件，不自动调度。

## 执行与取消

`JobManager` 为每个运行任务持有：

- `asyncio.Task`
- `asyncio.Event` 取消信号
- 进度回调

处理器必须在准备输入、供应商提交前、每次供应商轮询、下载前、校验前和保存前检查取消信号。

取消排队任务时直接标记 `canceled`。取消运行任务时设置取消信号并取消本地协程。只有任务仍处于非终态且未收到取消请求时，处理器才可写入最终资产状态，从而防止取消后的迟到响应污染项目。

供应商客户端增加可选的进度回调、取消信号和供应商任务 ID 回调。若未来某供应商支持远端撤销，则由对应适配器实现；当前没有可靠撤销能力时只执行本地终止。

并发上限沿用现有配置常量，按任务类型使用独立 semaphore，避免视频任务阻塞脚本或图片任务。

## API

新增：

- `POST /api/projects/{project_id}/jobs`
  - 创建单项任务或批次。
- `GET /api/projects/{project_id}/jobs`
  - 查询当前项目任务，支持状态和批次过滤。
- `GET /api/projects/{project_id}/jobs/{job_id}`
  - 返回任务详情、事件、错误与质量报告。
- `POST /api/projects/{project_id}/jobs/{job_id}/cancel`
  - 取消单项任务。
- `POST /api/projects/{project_id}/jobs/{job_id}/retry`
  - 基于输入快照创建重试任务。
- `POST /api/projects/{project_id}/job-batches/{batch_id}/cancel`
  - 取消批次中的排队与运行任务。

创建任务返回 HTTP 202。任务响应统一包含：

- `job_id`
- `batch_id`
- `state`
- `stage`
- `progress`
- `target`
- `can_cancel`
- `can_retry`
- `error`
- `quality`
- 时间戳

现有同步 API 保留给兼容调用和 Gradio 调试界面；Studio 的耗时生成入口迁移到任务 API。兼容层内部不得创建第二套并发任务状态。

兼容端点必须通过同一个 `JobManager` 创建任务，然后等待该任务进入终态并转换成旧响应格式；不能直接绕过任务管理器调用 Agent。`/api/script` 原有的自动创建项目能力只保留在兼容层，Studio 在提交新任务前必须已有明确的当前项目 ID。

## 错误模型

错误分类：

- `authentication`
- `network`
- `rate_limit`
- `quota`
- `timeout`
- `validation`
- `provider`
- `canceled`
- `internal`

错误结构包含：

- `code`
- `category`
- `message`
- `suggestion`
- `retriable`
- `http_status`
- `provider_status`

供应商错误通过集中分类器规范化。对外消息不得包含密钥、认证头、本地敏感路径或未清洗的完整响应。内部日志同样使用脱敏后的上下文。

## 质量控制

### 生成前检查

- 任务目标属于当前项目。
- 提示词非空且包含任务所需约束。
- 必需参考图存在、可读且与项目资产版本一致。
- 图片视图、视频时长、尺寸、宽高比和供应商参数合法。
- 批量任务只创建缺失项，不覆盖已生成版本。

### 确定性检查

图片：

- 文件存在且可由 Pillow 完整解码。
- 尺寸和宽高比符合目标容差。
- 文件不是近乎纯色/空白。
- 无严重模糊或明显损坏。

视频：

- ffprobe 可识别视频流和编码。
- 文件可解码，时长在供应商允许误差内。
- 采样帧不是持续黑屏或完全静止。
- 下载文件不是错误页或空文件。

确定性检查失败后，在同一任务中自动重试一次。第二次失败进入 `failed`，错误中说明两次失败原因。自动重试不得超过一次。

### 主观检查

当配置的模型明确支持视觉输入时，使用生成媒体采样与当前提示词/参考图检查角色、场景、道具和内容一致性。结果只产生 `warning` 和可执行建议，不自动重新生成。

模型不支持视觉输入、视觉审核调用失败或用户未配置相关服务时，质量报告明确标记 `skipped` 及原因，不生成虚假评分，也不影响确定性检查结果。

每个图片/视频版本保存对应质量摘要，历史版本切换时显示该版本自己的报告。

## 前端交互

### 当前项目任务入口

顶部步骤栏增加“任务”入口和运行数量。抽屉严格按 `appState.projectId` 查询，项目切换时停止旧轮询、清空列表并加载新项目任务。

抽屉默认按进行中、失败、已完成分组，任务行显示：

- 类型和目标名称
- 真实阶段与进度
- 开始时间和耗时
- 简短错误或质量警告
- 终止、重试、查看详情操作

前端每两秒轮询当前项目任务。异步响应继续使用现有项目 ID 与会话令牌校验，旧项目响应不得更新当前界面。

### 生成按钮

- 空闲：生成/重新生成/生成缺失资源。
- 排队或运行：终止/终止本批次，并显示 `x/y`。
- 失败或中断：重试。
- 已完成：恢复正常重新生成入口。

终止操作必须确认。确认文案明确说明本地终止与供应商可能继续计费的边界。

卡片和制作工作台从任务数据派生状态，不再各自维护互相冲突的 loading 标记。原底部假进度条移除。

## 部分成功与一致性

批量任务中的每个子任务独立提交和保存。成功子任务立即创建资产版本；失败或取消子任务不覆盖已有资源。父批次根据子任务聚合生成、跳过、失败和取消数量。

所有任务在保存前重新加载项目状态并校验目标仍存在。项目被切换、资产被删除或剧本重解析导致目标失效时，任务进入 `canceled` 或 `validation` 失败，不得把旧结果写回新状态。

供应商生成与下载在项目锁外执行；最终资产合并在 `JobManager` 的项目级写锁内完成。处理器进入写锁后重新读取最新 `DramaState`，只合并当前目标对应的资产或版本，不得用任务启动时的完整状态覆盖其他并发任务已经写入的结果。每个任务在创建时确定版本 ID，并在保存前检查该版本是否已经存在，保证重复回调和保存重试幂等。

## 测试

后端测试覆盖：

- schema 幂等迁移和 WAL 配置。
- 合法状态转换与非法转换拒绝。
- 服务重启把非终态任务标记为 `interrupted`。
- 单项取消、批量取消、取消后的迟到结果隔离。
- 手动重试创建新任务并保留历史。
- 当前项目隔离和跨项目访问拒绝。
- 真实阶段进度单调更新。
- 认证、网络、限流、余额、超时和供应商错误分类。
- 批量部分成功与补齐缺失项。
- 确定性质量失败只自动重试一次。
- 主观警告不触发付费重生成。
- 任务事件和响应不泄露密钥。
- 旧同步 API 继续通过兼容测试。

Mock 图片、视频和 LLM 服务必须支持可控的延迟、进度、取消、失败与迟到成功，不消耗真实 API。

浏览器验收覆盖：

- 剧本、三类图片、视频、音频和合成的任务提交。
- 单项按钮再次点击终止。
- 批量按钮终止整个批次。
- 刷新页面后状态恢复。
- 失败详情和重试。
- 项目快速切换后任务列表与界面不串项目。
- 质量警告和“未执行视觉审核”状态。

最终运行全量 `pytest`，要求现有测试与新增回归测试全部通过。

## 不在本次范围

- 不引入 Redis、Celery、RQ 或多机 worker。
- 不保证供应商端任务一定可撤销。
- 不在服务重启后自动续跑或自动重提任务。
- 不因主观质量警告自动重新生成。
- 不全面拆分现有前后端单体文件。
- 不重做移动端界面。
