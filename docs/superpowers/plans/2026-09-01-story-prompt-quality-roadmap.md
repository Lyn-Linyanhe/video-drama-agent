# 分镜提示词质量问题与改造路线

> **文档状态：调查结论与实施计划（2026-09-01）**  
> **当前阶段：只完成调查与计划，尚未修改代码**  
> **范围：分镜提示词生成、时间轴组装、视频提示词拼接；暂不处理 Kimi 审核**

## 一、结论先行

当前项目的问题不是单纯的“模型写得不够好”，而是分镜生成链路存在一套会主动压缩、删除、改写剧情的规则。

最核心的不合理设定是：

> “这一镜和上一镜相比增加哪些差异。”

这套设计适合做视觉连续性的增量描述，不适合直接承担剧情分镜生成。视频模型每次生成单镜时，拿到的是当前镜头的提示词，并不会可靠记住上一镜的完整剧情。因此，最终提示词必须是：

> **当前镜头独立、自包含、按顺序可执行的完整分镜指令；上一镜只能作为连续性参考，不能成为理解当前镜头的前置条件。**

当前链路实际效果更接近：

```text
结构化剧本
  → 差异摘要
  → 长度截断
  → 模板推断
  → beat 裁剪
  → 固定限制拼接
  → 视频模型
```

这会导致：

- 人物、地点、道具通常还在；
- 但动作因果、对白后反应、关键道具意义、反转、结尾状态容易消失；
- 镜头之间可能提前泄露后续动作；
- 总时长字段可能正常，但单镜内部剧情承载不足；
- 视频画面“看起来相关”，但观众无法完整理解故事。

## 三、必须调整的核心理念

### 3.1 差异模式降级为内部优化，不再作为语义契约

当前生效的提示词契约位于：

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\agents\visual_prompt_agent.py:507-520
```

当前关键规则包括：

> “输出紧凑、可验证的视觉差异数据。”

> “不要输出可由剧本和项目约束直接推导的完整长 prompt；后端会统一组装……”

这两句现在不应继续作为主要生成理念。

建议改成：

```text
每个镜头必须输出独立、自包含的完整叙事动作计划。
可以引用稳定的角色、地点和道具资产锚点，但不能省略当前镜头的动作链、对白、关键反应和结束状态。
上一镜只用于提供连续性参考，不是当前镜头理解剧情的必要前提。
```

### 3.2 “一镜只推进一个主要动作”必须取消

当前至少有三处重复限制：

- `visual_prompt_agent.py:518`：一镜只推进一个主要动作；
- `timed_prompt_composer.py:2041`：只表现一个主要动作节拍；
- `prompt_composer.py:65-68`：单一机位和一个主要动作节拍。

这把两个不同概念混成了一个概念：

```text
单镜头连续拍摄 ≠ 单镜头只能有一个动作
```

合理目标应是：

```text
一个镜头可以包含多个连续动作节拍；
每个节拍有顺序、时间范围、起始状态和结束状态；
不能为了满足数量上限静默删除剧本事实。
```

## 四、最高优先级：处理 beat 数量限制

### 4.1 当前限制为何严重

文件：

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\timed_prompt_composer.py
```

当前存在三层限制：

#### A. 无条件最多保留 5 个 beat

约 `1793-1803` 行：

```python
return beats[:5]
```

第 6 个及之后的 beat 会被直接丢弃，而且不会判断它是不是：

- 原剧本明确动作；
- 关键对白；
- 反转揭示；
- 关键道具变化；
- 结尾状态；
- 必须承接下一镜的连续性事实。

#### B. 按时长再次强制限制 beat 数量

约 `1930-1937` 行：

```python
if total <= 5.5:
    return 2
if total <= 8.0:
    return 3
if total <= 11.0:
    return 4
return 5
```

这实际上把镜头时长错误地当成了剧情动作数量上限。

#### C. 超限时固定删除“讲故事”的内容

约 `1945-1951` 行：

```python
removal_priority = [
    "emotion_landing",
    "prop_emphasis",
    "reaction_pan",
    "flashback",
    "continuity",
]
```

被优先删掉的正是：

- 情绪落点；
- 关键道具强调；
- 人物反应；
- 回忆和线索；
- 上下镜承接。

这些不应被默认视为低价值内容。

### 4.2 第一轮最值得做的改造

我建议第一轮不要直接把 beat 数量改成“无限”，而是采用**保真优先、禁止静默删除**的策略：

1. 删除 `return beats[:5]` 这种无条件截断；
2. 删除按 2-5 个 beat 的固定裁剪；
3. 为 beat 区分来源：
   - `script_required`：来自剧本动作、对白、道具、结尾状态；
   - `continuity_required`：当前镜头必须承接的状态；
   - `generated_support`：模型或组装器补充的镜头语言；
4. 任何 `script_required` 和 `continuity_required` 不得静默删除；
5. 只有 `generated_support` 可以在过载时合并或降级；
6. 如果镜头时长不足以承载全部必需 beat，返回明确诊断：

```text
当前镜头包含 N 个必需动作，预计需要 M 秒，但当前仅分配 T 秒。
系统不会静默删除剧情；请延长镜头或拆分镜头。
```

### 4.3 为什么这是最快得到正反馈的改动

这个改动可以最快验证用户的核心感受，因为它直接作用于：

- 动作是否完整；
- 对白是否完整；
- 道具是否完成揭示；
- 人物反应是否保留；
- 镜头结尾是否落地。

首轮验证不需要立刻调整视频模型，也不需要先改 Kimi。只要用同一个结构化剧本重新生成分镜提示词，对比：

```text
旧版：beat 被截断
新版：必需 beat 保留并报告超载
```

就能快速观察到：

- 最终提示词是否明显更接近剧本；
- 关键剧情是否重新出现；
- 是否出现“提示词过载”的真实案例；
- 哪些镜头需要拆分或延长。

### 4.4 第一轮改造的验收条件

至少建立以下测试：

- 6 个 beat 的镜头不会无提示地丢掉第 6 个；
- 关键动作位于第 6 个 beat 时仍被保留；
- 关键对白位于后部时仍被保留；
- 关键道具变化位于后部时仍被保留；
- 结尾状态位于后部时仍被保留；
- 时长不足时产生 `shot_overloaded` 诊断，而不是静默裁剪；
- 自动补充的普通镜头语言可以合并，但不能挤掉剧本事实；
- 旧有简单镜头不会被无故扩写成复杂多镜头。

## 五、除 beat 限制外，目前其他不合理规则

### P0：时间轴和视频结构定义冲突

#### 1. 15 秒硬上限与上游时长不一致

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\timed_prompt_composer.py:2020
```

```python
total = max(2.0, min(float(shot.duration_sec or scene.duration_sec or 5), 15.0))
```

但其他层允许：

- `Scene.duration_sec`：3-30 秒；
- `ShotPrompt.duration_sec`：3-60 秒。

这会造成 20-30 秒镜头的文字时间轴只覆盖前 15 秒，剩余时间交给模型自由发挥。

建议：统一时长契约，以当前镜头真实时长为准；若视频 provider 有单次时长上限，应显式拆镜或报错，不能只截文本时间轴。

#### 2. “两个时间戳 = 计划剪辑”误判

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\prompt_composer.py:40-50
```

当前只要有两个时间标记就会被认为是计划剪辑，但单镜头连续时间轴本来就会有多个时间段。因此同一提示词可能同时包含：

- 单镜头连续完成、不切镜头；
- 计划剪辑规则、按时间轴切换。

建议增加显式结构字段区分：

```text
shot_mode = continuous_take | planned_edit
```

不要用时间数字数量猜模式。

#### 3. 时间轴最多解析四段

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\timed_prompt_composer.py:575-603
```

当前使用 `matches[:4]`，第五段及之后会被丢失，并且前四段还会重新缩放填满总时长。

建议：完整解析全部时间段；不够承载时报告过载，不要悄悄删掉后续剧情。

### P0：对白和语音信息可能丢失

#### 4. 对白只保留前三句

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\timed_prompt_composer.py:454-461
```

当前存在：

```python
for line in lines[:3]:
```

第四句以后会静默消失，但这些对白仍可能参与时长估算，导致时长和内容不一致。

建议：完整保留对白；长对白拆成多个对白节拍或拆镜；不能按固定前三句截断。

#### 5. 电话、录音和画外音可能只保留声音形容词

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\timed_prompt_composer.py:1674-1685
```

电话分支优先取可见角色台词，画外角色可能只剩“苍老声音”“紧张声音”等描述，关键电话内容不进入提示词。

建议将语义内容和画面可见性分开：

```text
speaker_visibility = on_screen | off_screen | voice_only
```

`voice_only` 仍必须保留完整台词，用于音频、字幕和画面反应。

### P1：剧本解析阶段不应擅自改写用户剧本

文件：

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\agents\script_agent.py
```

#### 6. “开头 3 秒抓人”

约 `44-45` 行：

#### 7. “中段快速推进、结尾必须反转/爽点”

约 `44-45` 行附近。

#### 8. “每场 5-10 秒优先、每场只承载一个核心动作”

约 `47` 行。

#### 9. “每句台词尽量不超过 20-30 字”

约 `48` 行。

这些规则可以作为“新剧本创作建议”，但不应进入“用户已有剧本解析”流程。已有剧本模式应该优先：

```text

```

而不是：

```text

```

可以作为 provider 适配限制，但不能作为剧本内容限制。超长场景应该显式拆分并保留动作链。

#### 12. 总时长不超过 180 秒

超过上限时应提示用户或分段处理，不能用缩短对白、删除反应和合并剧情来满足限制。

只要道具没有被检测到，就可能自动增加“大特写/插入缓慢推近”。道具存在不等于本镜必须特写。

```

```

建议：补强只能补充现有 beat 文本；不能在时间轴外追加新的景别和镜头。

### P1：模板触发不应靠宽泛关键词猜剧情

#### 17. 普通编号信件被识别成闪回

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\timed_prompt_composer.py:816-819
```

任意“第几封信”都可能触发闪回/叠加模板，但编号信件本身不等于回忆画面。

#### 18. “清楚可见”“写着”等词触发道具插入

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\timed_prompt_composer.py:687-691
```

普通可见性描述不等于剪辑要求，不应自动变成大特写或插入镜头。

#### 19. 通用合成器内嵌题材特定模板

`timed_prompt_composer.py` 中存在针对：

- 监控、电箱、储物柜、黑衣人、录音机；
- 铜钟、铁盒、暗道、齿轮；
- 便利店、玻璃门、黑伞、街对面；

等特定悬疑事件的模板。

通用模块不应因为命中“钥匙、门、录音、照片”等普通词就套用固定故事叙事。应改为结构化事件类型或由当前镜头事实显式触发。

### P1：稳定性和项目配置不应被无条件覆盖

#### 20. 上下镜承接状态可能在定时重建中丢失

`visual_prompt_agent.py:1423-1438` 会生成“顺承上一镜”，但 `timed_prompt_composer.py` 的字段白名单没有稳定保留该段。

建议把连续性拆成结构化字段，在最终提示词中有明确位置，而不是依赖普通文本段落。

#### 21. 运镜约束互相冲突

`visual_prompt_agent.py:518` 要求每个时间段同时写镜头运动和主体动作；但对白模板使用“固定”，`prompt_composer.py:81-82` 又要求对白镜头限制运动幅度。

建议：镜头运动可以为“固定/无明显运动”，不应该强迫每个时间段都写出推拉摇移。

#### 22. 无条件注入手机亮度、雨势等连续性条件

当前模板无论场景是否存在手机或雨，都可能加入手机屏幕亮度、雨势/天气连续等约束。

建议只根据当前项目和镜头事实动态生成连续性锁定。

#### 23. 画幅、光照、运动模糊存在硬编码冲突

涉及：

```text
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\services\prompt_composer.py:75-86
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\agents\video_gen_agent.py:758-760
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\agents\video_gen_agent.py:1233
E:\影视agent\video-drama-agent-main(2)\video-drama-agent-main\src\config.py:95
```

问题包括：

- 项目比例可能被无条件写成 9:16；
- 场景原本是夜景、烛光或硬光，却被追加自然光、柔和荧光灯、柔和漫射光；
- “自然运动模糊”和“避免运动拖影”同时出现。

这类问题会影响视频视觉质量，但优先级低于剧情保真。

#### 24. 正向剧情文字与负面“文字”冲突

当前默认负面词包含“文字”，但某些镜头又要求纸面字迹、短信或地图标注清楚可见。建议区分：

```text
禁止字幕/水印/logo
允许剧情内文字区域；准确文字交给后期叠加
```

## 六、建议的逐步改造顺序

### 阶段 0：建立可复现基线（不改剧本）

固定以下样本：

- 《麦琪的礼物》：12 镜头，92 秒；
- 《末世》：10 镜头，77 秒；
- 《雨夜第七封信》：15 镜头，140 秒；
- 另选一个包含长对白和多动作的项目。

每个项目保存：

- 结构化剧本；
- 当前 generation prompts；
- 每镜动作/对白/道具/结尾状态；
- 最终提示词；
- 每镜时长和实际视频时长；
- 生成模型和请求参数。

### 阶段 1：先处理 beat 限制（第一优先级）

目标：禁止剧情 beat 静默丢失。

先做单元测试，再做最小实现：

- 让 beat 携带来源和重要性；
- 不再固定截断到 5 个；
- 不再按 2-5 个硬删；
- 必需事实保留；
- 过载时显式报错或警告；
- 只合并生成型镜头辅助描述。

验收：用《麦琪的礼物》镜头 1、4、9、12 和《末世》镜头 8、10 回归，检查关键动作和结尾状态是否重新出现在最终提示词中。

### 阶段 2：让每镜成为自包含提示词

目标：当前镜头脱离上一镜文本也能被理解。

- 当前镜头保留完整动作链；
- 上一镜只作为结构化 continuity 参考；
- 每镜明确 start_state 和 end_state；
- 当前镜头不得只出现“继续”“保持”“产生反应”等空泛语句；
- 稳定资产锚点与剧情动作分开。

### 阶段 3：统一时间和对白契约

- 去除 15 秒硬上限或改为显式 provider 约束；
- 时间轴完整解析，不限制四段；
- 取消对白前三句；
- 长对白按时间和镜头拆分；
- 明确 `continuous_take` 与 `planned_edit`；
- 解决对白估时与实际渲染内容不一致。

### 阶段 4：降低模板自动改写

- 模板只由结构化事件类型触发；
- 关键词只能作为候选，不得直接套模板；
- 不自动增加未被剧本支持的反应、特写、角色和地点；
- 不因为资产缺失就强行改变构图；
- 覆盖补强必须进入已有时间段。

### 阶段 5：修正剧本解析的“创作规则污染”

对已有剧本与想法创作分开：

- 用户已有剧本：忠实解析、拆镜、标记风险；
- 用户只有想法：允许使用钩子、节奏和反转建议；
- 不因可生成性直接删除原剧情；
- 超长剧本采用分段解析，不静默压缩。

### 阶段 6：最后再验证视频模型归因

只有提示词达到以下条件后，才把剩余问题归因给视频模型：

- 当前镜头事实覆盖完整；
- 关键对白和道具没有丢失；
- 动作顺序明确；
- 时间轴与视频时长一致；
- 无跨镜头污染；
- 无错误模板触发。

然后对同一模型做旧提示词/新提示词 A/B，最后再比较不同视频模型。

## 七、第一轮改造的范围建议

为了快速获得反馈，第一轮不要同时改所有规则，建议只处理：

1. beat 硬裁剪；
2. 第四句以后对白丢失；
3. 15 秒时间轴硬上限；
4. “一镜只推进一个主要动作”三处文案。

其中核心是第 1 项。第一轮完成后重新生成同一项目的分镜提示词，不必马上生成完整视频，就能比较：

- 关键剧情出现率；
- 剧本动作覆盖率；
- 提示词是否仍然跨镜污染；
- 单镜动作是否更完整；
- 提示词是否出现过载。

## 八、暂不处理事项

本轮明确暂不处理：

- Kimi 审核逻辑；
- 原始剧本内容；
- DeepSeek 模型和思考档位；
- 视频模型能力本身；
- 音频、字幕和后期合成；
- 历史项目迁移。

## 九、最终目标

最终分镜提示词应满足：

```text
1. 每镜独立可理解；
2. 结构化剧本明确事实不被静默删除；
3. 动作按顺序执行并有起止状态；
4. 对白完整且能定位到画面/声音；
5. 关键道具和反转不因模板裁剪而消失；
6. 镜头超载时明确告警，不偷偷摘要；
7. 上一镜只用于连续性，不是剧情理解前提；
8. 组装层负责组装，不重新编剧；
9. 时间轴与实际生成时长一致；
10. 视频模型拿到的是完整、明确、可执行的当前镜头指令。
```
