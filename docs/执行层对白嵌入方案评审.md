# 执行层对白嵌入方案评审

日期：2026-09-08  
项目样本：`output/9559d0cd84ca`（《麦琪的礼物》）  
范围：只评测试结果，未写回 `meta.json`，未覆盖历史视频。

## 结论

**方向可行，当前形态不能落地。**

把对白嵌进 `【动作时间轴】`、有参考图时去掉身份档案、不再单独开 `【对白】` 块，这三件事是对的，也更接近手工改过的 8-1。  
但这一层只是把「已经绑好的子镜头」重新排版。它既不能纠正错误的剧本绑定，也不能保证页面上看到的就是模型吃到的，更没有经过真实快乐小马对照。现在落地，只会让错误对白念得更清楚，同时让「改提示词 / 保真门禁 / 实际请求」三套文本继续打架。

## 方案实际做了什么

不重跑 DeepSeek。子镜头物化 + 执行层把台词写成：

```text
这时候吉姆："你已经把头发剪掉了？"
```

测试中确认：

- 有对白的子镜头：说话人 + 原句出现在时间轴里
- 无对白子镜头：不发明「这时候」
- 镜头 5 / 7 / 8 / 12：对白不再串到别的子镜头
- 7-3 不再把整段长对白重复嵌一遍
- `。，这时候` 标点错误已在测试中消失
- 相关单测 26 passed

这些只能证明「排版层」在样本上工作，不能证明成片会变好。

## 找茬

### 1. 发给模型的并不是执行层本身

`src/agents/video_gen_agent.py` 的 `_build_multi_reference_prompt` 会先拼：

- 竖屏 9:16 / 电影级质感
- `[Reference tags]` / `[Reference binding]` / 参考图 N
- `[Reference hierarchy]` 英文规则
- `【单镜头连续拍摄规则】`
- 然后才追加 `【执行提示词】` + 执行层
- 最后 `return " ".join(lines)`

也就是说，即使用户手写那种短时间轴，真实请求仍会被参考图前言和结构规则包一层。  
本方案最想解决的「对白被长文淹没」，在发送路径上没有真正消失。只改执行层、不改发送拼接，效果会被吃掉。

### 2. 用户看到的、门禁检查的、模型吃到的是三份文本

| 位置 | 用的文本 |
|---|---|
| 页面上的分镜提示词 | 存盘父提示词 / 旧 `unit.prompt` |
| 保真门禁 `snapshot_prompt_mismatch` | 存盘 `source_prompt` |
| 视频请求 | 参考图前言 + 执行层 |

这会直接导致：

- 用户按页面长文判断质量，和真实请求无关
- 一改存盘稿，门禁认为快照过期，再次出现「提示词存在确定性保真问题：禁止生成」
- 调试时无法回答「模型到底看见了哪句对白」

在三套文本对齐之前，这套方案不适合进生产。

### 3. 错误绑定会被放大，不会被修好

执行层只是把结构化剧本里已经绑上的台词念得更显眼。样本里至少有这些上游错误：

**镜头 6-2**  
动作是珠宝柜台买白金表链。  
绑上的台词却是：

> 假如吉姆看我一眼不把我宰掉的话……只有一元八角七，我能干什么呢？

这句属于剪发前只剩 1.87 元的心理活动，不是卖掉头发拿到 20 美元之后买表链该说的话。  
旧方案里它可能被长文淹没；新方案会让快乐小马更可能把这句念出来。

**镜头 5-4**  
5-3 已经「德拉脱下帽子」。  
5-4 动作是抓发掂量，台词却仍是「揭掉帽子，让我看看发样。」顺序反了。

**镜头 7-2**  
动作是烫完头发、点炉、煮咖啡。  
台词却是回家后对吉姆说的「别那样盯着我……」。吉姆这一场还没进门。  
执行层会把这场独白/对白变成炉边说话，和后一场进门对峙打架。

这些不是排版 bug，是剧本解析 / 分镜拆拍 / 对白绑定问题。本方案没有审核「这句话该不该出现在这一镜」，所以不能宣称「下次自动生成也会像手写 8-1」。

### 4. 没有改 DeepSeek 生成端

用户要的是：下一次系统自动生成的分镜提示词，质量接近手写稿。  
本方案明确不重跑、不改 DeepSeek 模板。父提示词仍然是身份档案 + 视觉套话 + 容量诊断。  
下次点「生成分镜」，旧长文还会回来，执行层再做一次事后翻译。这是补丁，不是生成质量。

### 5. 对白-only 子镜头仍然是空动作

测试输出里，7-3、8-4、12-2 仍是：

> 德拉保持当前站位、表情和关键道具，把本镜对白完整清楚地说完……

这和手写 8-1 的差距正在这里。手写稿是「具体动作 + 当场那句话」。  
占位动作会让模型拍成站桩念词。长对白镜头尤其危险。

### 6. 时长和费用问题没动

- 7-2：15s 里塞进大段对白
- 8-4：11s 里塞进德拉那大段解释
- 12-2：8s 里塞进买表链的完整台词

把台词嵌进时间轴，不会让快乐小马凭空变出足够口型时间。费用和「成片比预期短 / 词没说完」的老问题还在。

### 7. 没有真实视频对照

本轮只有文本 dump 和单测。没有用同一参考图、同一 seed、快乐小马 1.1-r2v 去对比：

- 旧存盘稿
- 新执行层
- 用户手写 8-1

在没有成片证据前，不能说「故事能讲完了」。

### 8. 实现上还有脆点

- 旧 `unit.prompt` 必须事后清洗，否则镜头 5 会留下 `【对白】` 并串词
- `_already_spoken_in_timeline` 只要看见引号或「这时候」就不再嵌套；动作描写里若出现引号，可能漏词
- 句末仍有 `。"。` 这种机械标点
- 保真审计仍看存盘稿，不看执行层，两边评分会分叉

## 分层责任

```text
原剧本 / 结构化剧本     用户负责；本方案不修
对白绑到哪一个子镜头     规划层；本方案不修，只会放大错误
父提示词怎么写           DeepSeek 生成端；本方案不修
子镜头时间轴怎么排版     本方案只做到这里
真正发出去的请求         仍被参考图前言和结构规则包裹
页面与门禁               仍看旧存盘稿
```

排版层单独变好，整条链路不会变好。

## 什么时候才可以再谈落地

同时满足下面几条，再考虑写回项目或给用户做视频测试：

1. 视频请求的主文本就是执行层时间轴；参考图约束单独、短、可关，不再 ` " ".join` 把所有块糊成一段。
2. 页面展示、保真门禁、请求快照使用同一份「将发送文本」。
3. 先修明显错绑：至少镜头 6 的 1.87 元独白不得出现在买表链；镜头 5 的「揭帽」不得出现在已经摘帽之后；镜头 7 对吉姆说的话不得出现在吉姆进门前。
4. 对白-only 子镜头必须有具体动作，或并回有动作的邻镜，禁止「保持站位把对白说完」。
5. 用快乐小马对 8-1 / 8-2 / 5-2 做真视频对照，而不是只看文本。
6. 若目标是「下次自动生成也像手写」，必须改 DeepSeek 分镜生成，而不是只做执行层翻译。

## 追加：2026-09-08 落地进展与已知遗留

按上面「什么时候才能谈落地」的清单，本轮把**代码 + 自动化测试**这条能确定的部分做实了，仍然**没有写回项目 meta、没有重跑 DeepSeek、没有做快乐小马真实对照**。全量回归 `1217 passed, 2 skipped`。

### 本轮确认/修复

1. **时长越界（原缺陷2）→ 判为无需修**：真实 HappyHorse 参数下镜头7是 5/15/6、镜头8是 4/7/4/11，全在 4–15s。之前的 3s/19s 只是导出脚本没传 provider min/cap 造成的假象。
2. **道具标签污染（原缺陷1）**：真实链路 `_build_multi_reference_prompt` 里 `白prop=0`、道具名还原成「白金表链」。存量 meta 里仍有一条早期写坏的 `白@prop:…` 父提示词，属脏数据，未回改。
3. **对白重复块**：`append_native_dialogue_prompt` 现在对已内嵌台词幂等，真实 8-1 里台词只出现 1 次，不再另挂 `【关键对白（必须出现）】`。
4. **核心块过度去重**：收窄为「核心与时间轴动作**完全相同**（忽略时间前缀与内嵌台词）时才删」，保留合法的首拍摘要，快照与执行两处测试同时通过。
5. **双句号 / 光线粘行**：`？"。` 与 `。，这时候` 消除；`【光线与色调】` 被 DeepSeek 黏在镜头行时，执行层拆回环境与视觉块。
6. **audio preflight native 分支**：纯 native 说话人不再被要求确认 TTS 音色。
7. **存稿 vs 执行层的身份锚点矛盾（4 项可视化回归）**：根因是 `visual_prompt_agent.py:2148` 无条件把父提示词身份塌缩成「以参考图为准」。已改回**存稿保留完整稳定身份**（作为可编辑事实与保真门禁依据），**由执行层在有效人物参考图覆盖时**塌缩——与 `test_prompt_execution_context.py:52` 一致。

### 已知遗留（本轮没解决，需下一步）

- **5-4 / 6-2 多说话人·内心独白的语义锚点**：单说话人命令型（镜头5 dlg2）靠 `_shared_dialogue_token` 已能提前锚定；但**多说话人**（索弗罗妮两句）与**无对象关键词的内心独白**（6 的「只有一元八角七」）仍落在「最后动作拍」兜底，可能仍偏晚。强行在主循环加多说话人启发式风险高、易把镜头8 等已验证配对改坏，故**不硬改**，留作观察项：更稳的做法是让 DeepSeek 源头把对白写成独立事件（`_dialogue_from_prompt` 的显式顺序），而非靠后处理猜锚点。
- **占位动作（7-3 / 8-4 / 12-2「保持当前站位完成对白」）**：执行层已有台词，但动作仍是占位句，不如手写版具体；需要「对白镜补一个与台词相符的说话动作」的小生成步骤。
- **三套文本仍分层**（页面存稿 / 保真门禁 / 实际请求）：本轮把存稿改回完整身份、把塌缩交给执行层，方向统一了，但**页面看到的仍不是最终 provider 请求**，需要 UI 展示执行层或明确标注「以下为模型实际收到的提示词」。
- **快乐小马真实对照未做**：上面全是单测+导出复验。下一步应选 8-1（短对白）、8-2（长对白）、9-2（拥抱+长表白）各生成一条，检查 ASR 是否能听到正确台词、口型与说话人是否对得上。欠费/额度需先解决。

### 这一版能不能落地

比上一版更可行：**执行层与真实链路已对齐、去重冲突已解、native 音频门禁已修、存稿/执行的身份职责边界讲清并有测试覆盖**。但仍**不能**宣称成片质量达标——因为 5-4/6-2 语义锚点、占位动作、真实快乐小马对照三件事还没过。落地顺序建议：先做快乐小马对照拿回真实听感证据，再决定要不要投入多说话人锚点的更重改造。
