# 剧本生成与解析流程

## 一、剧本来源

项目支持两种方式获取剧本：

- **AI 创意生成**：根据用户创意生成可编辑的中文剧本草稿。
- **导入已有剧本**：粘贴或导入用户已有的剧本正文。

AI 生成和导入阶段只保存剧本文本，不生成角色、场景、道具或分镜数据。

## 二、确认并解析

用户编辑草稿后点击“确认并解析”，系统创建 `script.analyze` 任务。

解析模型会根据完整剧本文本输出结构化剧本，包括：

- 剧本标题、类型、梗概和总时长
- 场景和镜头顺序
- 场景地点、出场角色和对白
- 动作描述、镜头方向和情绪
- 转场与镜头连续性
- 角色、场景和关键道具资产清单
- 镜头与资产之间的绑定关系

人物、场景和道具目前不是三个独立任务，而是同一次结构化剧本解析中的不同部分。

## 三、后端校验

模型返回结果后，后端会进行确定性处理：

- 修正镜头和转场时长；
- 合并同名角色、场景和道具；
- 生成稳定的资产 ID；
- 重建 `shot_ids` 和镜头绑定关系；
- 删除不符合关键道具定义的普通物品；
- 检查每个镜头是否绑定正确场景；
- 检查角色、场景、道具引用是否一致。

校验失败时，当前流程可能追加错误信息并重新请求整份结构化剧本。

校验通过后，结构化剧本和资产清单会保存到项目状态中。

## 四、视觉与分镜提示词

结构解析成功后，系统自动创建 `script.visualize` 任务。

该任务会再次读取剧本、角色、场景、道具和镜头绑定，并生成：

- 项目整体视觉风格；
- 角色稳定外貌描述；
- 场景视觉设计；
- 每个镜头的动作时间轴；
- 摄像机运动、光线和环境差异；
- 镜头级正面和负面提示词；
- 可发送给视频模型的完整提示词。

视觉阶段完成后，项目的 `visual_stage` 变为 `ready`，资产生成、分镜生成和视频生成操作才会完全开放。

## 五、任务顺序

```text
AI 创意 / 导入剧本
        ↓
可编辑剧本草稿
        ↓ 用户确认
script.analyze
        ↓
结构化剧本 + 角色/场景/道具清单
        ↓
script.visualize
        ↓
视觉设计 + 分镜提示词
        ↓
图片、视频、配音和成片生成
```

## 六、耗时主要来源

当前耗时主要集中在两个 LLM 阶段：

1. **结构化剧本解析**：一次性输出剧本、场景、角色、道具和绑定关系，输出结构较大，校验失败时可能重试。
2. **视觉提示词生成**：再次读取完整剧本和资产清单，为所有镜头生成视觉设计和视频提示词。

本地 JSON 保存、资产合并和字段校验通常不是主要瓶颈。真正的视频生成属于后续供应商任务，不属于剧本解析阶段。

## 七、JSON 的作用

JSON 仍然是项目内部的重要数据格式，用于：

- 前后端传递结构化剧本；
- 保存项目状态；
- 校验资产和镜头绑定；
- 记录任务、版本和提示词快照；
- 支持项目恢复、重试和历史版本追溯。

后续优化方向是减少模型输出的冗余 JSON，由模型负责理解剧本，由后端负责生成 ID、绑定关系和默认字段。
